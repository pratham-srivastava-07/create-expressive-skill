# Architecture

Projects generated by `create-expressive` follow a strict layered architecture with a
one-directional dependency flow:

```
Routes → Controllers → Services → Repositories → Prisma
```

Each layer only knows about the layer directly below it. This keeps business logic
testable, data access swappable, and HTTP concerns isolated.

## Layers

### `src/routes/`
Maps HTTP method + path to a controller function. No logic. Each resource has its own
file (`user.ts`) and is mounted in `routes/index.ts`.

### `src/controllers/`
The HTTP boundary. Reads validated input, calls the appropriate service, and shapes the
response (status code + body). Controllers never talk to Prisma directly and never contain
business rules. Registered in `controllers/index.ts`.

### `src/services/`
Business logic lives here — orchestration, rules, hashing, token issuance. Services call
repositories for data and throw `AppError` for expected failures. Registered in
`services/index.ts`.

### `src/repositories/`
The only layer that touches Prisma. Pure data access: `findById`, `create`, `update`,
`delete`. No business rules. Named `<entity>.repository.ts`.

### `src/validators/`
Zod schemas describing request shapes. Used before controllers hand data down. Registered
in `validators/index.ts`.

### `src/interfaces/`
Shared TypeScript types and DTOs (`user.ts`, `error.ts`).

### `src/middlewares/`
Cross-cutting Express middleware. `auth.ts` verifies JWTs and attaches the user.

### `src/utils/`
`AppError.ts` (typed operational errors) and `error.ts` (centralized error handler that
turns thrown errors into consistent HTTP responses).

### `src/config/`
`env.ts` — reads and validates environment variables in one place.

### `src/helpers/`
`prisma.ts` — the singleton Prisma client the repositories import.

### `prisma/`
`schema.prisma` — the data model. Every new entity adds a model here.

## Why this matters for tokens

Because the layout is fixed, Claude never has to ask "where do controllers go?" or
"do you use a service layer?". The structure above is the answer, permanently — which is
the whole point of loading this skill.
